# 审计问题修复记录

对应 [修复前审计](audit-2026-09-07.md)。本次修改保留工作区原有改动，验证使用独立数据库，没有更改实际业务数据。

## 已修复

| 问题 | 修复后的行为 |
| --- | --- |
| 运行中重试导致假完成 | 前端禁用不合法的重试操作；后端检查状态并原子切换，冲突返回 409；存在待执行项时不能进入 completed |
| 取消后继续发出请求 | 获取并发名额后和重试前读取最新取消标记；尚未发出的调用停止，已返回结果仍可按既定策略保存 |
| 整批等待后才保存进度 | 每个完成响应单独持久化，慢请求不会阻塞其他已完成结果落库 |
| 缓存结果被误标严格可比 | 同时核查所选配置、每个样本的实际评分修订／Prompt／模型／地址／分值尺度以及完整覆盖率，返回具体差异说明 |
| 实时推送截断历史任务 | 任务、结果和模型记录增加服务端分页与检索；任务状态筛选在分页前执行；实时通知刷新查询，不覆盖列表内容 |
| 提交后任务难以定位 | 提交成功后跳转到指定任务，已快速完成的任务也不会被“活动”筛选隐藏 |
| 分数只在当前页排序 | 后端在分页前按分数排序，空分数排在最后；切换排序回到第一页 |
| 结果详情停留在旧状态 | 活动结果订阅变更、断线自动刷新；重试后刷新相关查询；切换任务重置页码和筛选 |
| 加载失败显示成空数据 | 页面区分加载、错误、空数据和已有结果；统一错误提示、重试入口、请求取消及刷新合并 |
| 导入失败只能关闭窗口 | 失败窗口提供“修改并重新核验”，保留输入路径或所选文件 |
| 重试次数 0 被改成 3 | 配置回填使用空值判断；保存中显示状态；取消后的 Prompt 表单不会串入旧内容 |
| 损坏 ZIP 返回 500 | 返回可操作的 400 错误，并清理本次解压失败产生的暂存目录 |
| 非法 Prompt／Tokenizer／阈值能保存 | 保存前校验模板、合法变量、Tokenizer 及评价器对应阈值范围；说明 JSON 花括号转义要求 |
| 核验后的预测被改动仍能提交 | 核验记录保存预测内容摘要；提交前复核摘要和完整 ID 集合 |
| 全部失败的语种消失 | 汇总包含每个语种的总数、成功、失败、取消和覆盖率；无成功评分显示缺失值；页面新增逐语种覆盖表 |
| 深色标题难读、1024 窗口溢出 | 修正统计标题颜色，窄屏自动收起导航，阈值区改为独立行，表格在容器内滚动 |
| 多评价器并行文案不符合实现 | 文案明确“评价器依次执行”，保留单个评价器内部的并发 |

查询与比较逻辑提取至 `backend/app/queries.py`，配置及模板验证集中至 `validation.py`；前端增加通用查询和任务变更 hooks，并拆出结果列表页面。分页保留旧接口，同时新增 `/tasks/page`、`/results/page`、`/model-runs/page`、`/tasks/changes`。

## 更新影响与剩余优化

无需数据库结构迁移。更新代码后需重新构建前端并重启 API、Worker。已经完成的历史提交仍保持幂等；更新前尚未提交、缺少预测摘要的核验记录需重新核验，接口会给出明确提示。

构建仍提示较大的依赖分块；测试依赖有一条 Starlette/httpx 弃用提示。二者未导致构建或测试失败。

审计中的数据预览、运行详情、导出、混淆矩阵界面、更深入的模块拆分、导入暂存保留期限、跨 Worker 调度和依赖体积优化仍属于后续改进。本次没有新增这些功能，也没有改变既定的明文密钥保存或宽松缓存策略。
