**已复现功能缺陷的修复**

| 问题 | 当前行为与保障 |
| --- | --- |
| BLEU 越界、LLM 非有限或类型错误配置仍可保存 | 参数前置校验；成功评分统一校验有限数值、量表、单位和响应 JSON；非法结果明确失败。BLEU 的极小满分浮点误差单独规范化 |
| 严格比较把无效评分也算完整 | 统计、筛选、聚合和比较共享有效评分条件；来源一致且成功样本集合相同仍不足以掩盖缺分 |
| 重复 Worker 恢复活跃任务并重复评分 | 数据库路径对应 OS 独占锁；持锁后才恢复，任务另有条件状态领取。进程退出后 OS 释放锁 |
| 并发提交同一报告生成两份提交和任务 | 核验之后原子认领报告；认领、数据发布与任务创建同事务，竞争请求返回同一结果 |
| 无效语种代码通过严格导入 | 源语种和预测语种共享格式校验，允许合法的未知代码及文字/地区标签；保留已有小写与空白规范化 |
| 同时改源文与参考译文漏报一项 | 两个变化维度分别计数，增加“源文与参考译文均变化”；界面说明计数允许重叠 |
| 在途请求仍显示等待评分 | 分配实际执行槽后标记 running；取消停止新调度，恢复时重新排队中断项 |
| 取消整任务失败没有可见反馈 | 显示服务端错误，保留弹窗和重试入口；浏览器注入 503 后再次取消通过 |
| 多余 manifest 数据集项无法删除 | 可删除没有对应预测文件的条目，按实际目录重新选择并核验 |

另增加明确的严格缓存选项 `strict_revision`。默认 `content_model` 继续兼容跨 Prompt/配置的同模型内容复用；严格模式要求评价器修订、Prompt 和服务地址同时匹配。强制评分仍可跳过历史缓存，任务内部重复内容继续去重。

阈值指标在界面统一称为“通过率”，API 的 `micro_accuracy` 等旧字段名保留兼容。语种识别同时提供总体准确率与已识别样本准确率，并分别说明召回率的分母。只覆盖一半样本且全部猜对的示例，现在显示总体 50%、已识别 100%、覆盖率 50%。

**导入：有界内存与后台恢复**

`ImportIndex` 逐行校验 JSONL，将排序、查重、内容哈希与版本差异所需数据写入私有临时索引；比较旧版本只流式读取 ID、语种与哈希。提交前重新生成索引并核对原报告，再直接从这一冻结快照批量写入，避免核验后重新读取已变化的原文件。

历史 dataset/prediction 内容哈希格式保持兼容；回归包含乱序 ID、Unicode 组合字符和换行。主库每 1,000 条使用一次批量 INSERT，任务项使用 `INSERT … SELECT`。临时索引使用后清理，不是额外的永久数据库。

新增持久化 `ImportCommitJob` 与后台 dispatcher：

- 页面提交后保存任务 ID，显示等待、重新核验、写入、完成或失败阶段；支持刷新恢复与顶栏历史查找。
- 同一核验报告只对应一个后台提交任务，重复请求不会新建。失败时可沿用服务端保存的评价配置重试。
- dispatcher 取得单机 OS 锁后才恢复中断请求。即使进程在数据已发布、后台状态尚未写回的间隙退出，重放也复用原版本或原 Submission/Task。
- 原同步提交 API 保留。后台任务复用同一套完整性校验和原子事务，并不发布半成品，也不显示虚构的逐行百分比。

最终导入复测使用与审查相同的 40 个语种、每语种 10,000 条、平均源文约 163 字节/参考约 195 字节，第二版本只改约 1% 参考译文。每个阶段为独立子进程；峰值 RSS 包含 Python/库与 SQLite 页面缓存。

| --- | ---: | ---: |
| 数据集核验 | 8.13 秒 / 563 MiB | 15.60 秒 / 74 MiB |
| 数据集提交 | 59.69 秒 / 625 MiB | 45.16 秒 / 111 MiB |

磁盘索引用额外 I/O 换取有界内存，因此核验并非每项都变快；不能把这项改造描述为全面缩短核验时间。数据集提交 SQL 数量由约 400,047 次降为 412 次。表中提交阶段含再次核验，不含 HTTP 上传/prepare；预测提交与任务项创建在 API 中是同一事务的不同工作，不能将单项计时当作整次提交耗时。

SQLite 仍只有一个同时写入者。大导入已后台化、写入已批量化，但一次多数据集提交的写锁时长仍随总量增长；本轮没有宣称持续多写者负载已经通过验收。

**Worker：完整规模运行结果**

每次最多装载 512 条，当前批次外的 ORM、缓存与响应对象不再长期驻留。完整进度仅在开始/恢复和终态校准，逐响应组累加完成、失败与缓存数。已返回的响应仍及时持久化，未因有慢请求而延迟整个批次落库。

终态均值使用按语种的和/数量，Corpus BLEU 累加 n-gram 充分统计量后统一计算，回归与 SacreBLEU 官方 `corpus_score` 一致。LLM 聚合只读取分数、单位及语种，不读取译文、参考全文或原始响应。

| 验证 | 结果 |
| --- | --- |
| 40 万条任务项创建 | 38.07 → 5.18 秒，峰值约 69 MiB |
| 待评项初始装载 | 原全量约 23.48 秒 / 2 GiB；新首批 512 条约 0.065 秒 / 68 MiB |

40 万条使用本地函数提供评分输出，真实执行队列、持久化和统计路径；不代表外部 LLM 的速度或评分质量。本次没有运行旧实现的完整 40 万条评分，因此不提供虚构的整轮加速倍数。当次未采集 SQLite 缓存配置，表中 RSS 与耗时仅代表该次运行；最终 32 MiB 缓存配置及后续聚合窄投影等收尾改动通过定向回归，未再次完整测量 40 万条 Worker 的耗时和峰值。详细边界见 [Worker 专项记录](optimization-2026-09-07/worker-changes.md)。

**查询：常用路径与首次统计分开计算**

新任务终态预计算按语种摘要及成功样本/实际评分来源的窄字段指纹；列表和比较无需加载完整 ScoreResult ORM。内部摘要与构建标记不出现在公开聚合中。重试、分值及相关统计来源变化会使摘要失效，构建标记避免并发修改后发布旧快照。

动态阈值仍按真实分数精确统计，单任务最多保留 8 个最近阈值；不能将默认阈值的通过数复用给另一个阈值。明细查询先定位当前页样本 ID，再读取所需字段，基本分页不再计数/排序全部评分联表。

在途结果详情订阅当前评价器任务及其父任务的变化，自动刷新合并为最多每 5 秒一次，避免其他任务每秒变化都触发大统计；手动刷新仍立即执行。
