## 逻辑修复

| 问题 | 修复后的行为 | 验证 |
| --- | --- | --- |
| 失败后取消，再重试失败项，被错误标为全部完成 | 根据实际逐句状态计算终态；任务、结果详情与统计均使用真实取消数 | 1 成功、5 取消时保持 partial_cancelled，父任务与数据集取消两条路径均覆盖 |
| 布尔评分被转换为 0/1 并持久化 | 仅接受有限 JSON 数值 0–10；布尔、字符串、null、集合、非有限值和越界值进入可重试错误路径 | 10 类异常输入与正常整数、浮点边界 |
| 空 choices、null content 等异常响应未按预期重试 | 显式校验响应结构；明确拒绝评分单独分类为不可重试错误 | 首次异常、第二次合法评分时实际调用 2 次并成功；明确拒绝仅调用 1 次 |
| 取消时聚合缺失，重试后取消仍展示旧 BLEU | 所有终态按当前成功子集重建聚合；活动任务与样本数不匹配的历史聚合不展示 | 4 → 5 成功样本后 corpus BLEU 更新为 40.563199，sample_count=5；开始前取消也覆盖 |
| 空白语种在提交时造成 500 | 先归一化再校验非空；旧核验报告中的无效清单返回可读 400 | 清单语种、样本语种和旧报告回归 |
| 旧版本重复只在提交时被数据库拒绝 | 核验阶段检查该数据集全部历史标签与内容哈希 | v1、v2 导入后重新核验 v1 即明确拒绝 |
| 修改并发数或原样保存覆盖隐藏参数 | 前端保留原配置并覆盖编辑字段，后端合并未提供字段；相同规范化配置避免无意义修订 | LLM 的 temperature=0.7、max_tokens=1024 保留；BLEU 的 smooth_value=0.5、effective_order=false 保留 |

## 日常操作改进

- 从任务卡片、结果详情和模型运行详情点击“再次评测”，选择最新评分服务修订或其他 Prompt。新任务复用同一个 InferenceSubmission 和 Prediction，不需要重新上传，不重复建立模型和预测记录。
- 原任务的“重试失败项”仍使用原配置快照。已验证失效凭证 r1 产生 6 条失败后，基于同一提交选择有效凭证 r2，可以完成 6 条评分；旧任务及其来源保留。
- 模型运行详情展示检查点、设备、精度、推理时间、代码版本、备注及解码参数。
- 任意历史 Prompt 版本可以复制成新版本，草稿状态明确可见；提交处说明缓存忽略 Prompt 和服务地址，验证新 Prompt 时需开启强制重评。
- 数据集版本增加分页样本预览、语种筛选和完整哈希复制，核验摘要及差异计数使用中文标签。
- 全部评分失败时，任务卡片和结果列表均提供失败明细入口；BLEU 聚合明确标注成功子集与样本数。

## 结构与兼容性

再次评测复用已有创建任务函数和数据表；样本预览复用现有分页 API。取消计数集中在查询模块并批量查询，终态判断集中在队列函数，API 直接从 queries 导入统计查询，减少不必要的模块依赖。本次没有增加依赖包或数据库表。

新增接口：

- `GET /api/submissions/{submission_id}`：已有提交的摘要及数据集版本。
- `POST /api/submissions/{submission_id}/evaluations`：用所选评价器修订和 Prompt 创建新任务，请求结构与原提交接口相同。
- `GET /api/model-runs/{model_run_id}`：运行详情和关联提交。

导入提交接口原有的幂等行为、历史配置不可变以及宽松缓存口径保持兼容。更新需重新构建前端并重启 API 和 Worker，无需数据库迁移。历史异常评分和错误任务终态不会自动修订；需要可信的新结果时，从原提交强制再次评测。
