# 评测结果、语言对与逐句评分易用性评审

本轮先将上一轮准确率与评分筛选功能保存为本地 commit `27c1118`，再重新检查用户如何找到结果、确认范围和核对异常。评审发现的主要问题是：结果列表没有实际成绩；数据集只显示语种数，实际语言藏在下拉框；核对时缺少精确版本关联，刷新又会丢失筛选条件。

## 处理原则

一次评测明确关联模型提交、不可变数据集版本、评价器修订和所选 Prompt。每条结果都应能确认这几个身份，再解释分数。不同数据版本或评价尺度的结果不自动混合成一个均值；比较时明确统一阈值并保留口径差异提示。

查看顺序为：**总体结果 → 语言对结果 → 逐句评分 → 同版本源文与参考译文**。每一步都带着前一步的范围，支持直接返回继续核对。数据集页面也能反向进入该版本的评测结果。

准确率继续采用用户确定的定义：得分 ≥ 阈值为正确，未评分计为未通过，分母为全量样本；加权平均准确率等于总正确数 / 总样本数。运行中的结果标为临时统计。平均分只统计有实际分数的样本，未评分保留原始状态供排查。

## 发现与已实施的改进

| 使用问题 | 改进 | 核对方式 |
| --- | --- | --- |
| 每次都要进入详情才知道成绩 | 列表直接展示加权准确率、正确数 / 总数、已评分平均分、未评分数与覆盖率 | 列表摘要和详情按同一评价修订默认阈值逐项一致 |
| 相同模型多次评测容易看错记录 | 展示数据版本、评价修订、Prompt 标签、提交时间、短评测编号；详情补检查点 | 对照任务身份，比较结果不会覆盖历史记录 |
| 看不出“多少准确率是在什么阈值下” | 阈值紧邻总体指标；临时调整有提示和恢复默认按钮 | 比较表进入详情继承本次对比阈值 |
| 数据集只写“几个语种” | 卡片和各历史版本展示中文名、原代码、目标中文及各自句数 | 按不可变版本的实际样本分组统计 |
| 从结果到数据集可能误看最新版 | 明确返回 dataset_id、dataset_version_id；核对按钮携带版本、语言、样本 ID | 用语言组成不同的新旧版本验收 |
| 某个分数有很多句，异常样本难定位 | 保留五种分数比较，新增完整样本 ID 查找及正确 / 低于阈值 / 未评分快捷入口 | ID 精确匹配，不把 `%`、`_` 当通配符 |
| 刷新和返回需要重新选择条件 | 列表和评分明细将筛选、阈值、排序、分页写入 URL；详情带返回列表条件 | 刷新、回退、重新打开链接均可复查相同范围 |
| 大量语种和图表把句子推到很远 | 语种表每页 10 行；逐句明细紧接语种表；图表下移并折叠，顶部有逐句入口 | 33 语种及窄桌面宽度验收 |
| 全部未评分的任务无法比较 | 总样本数大于 0 的结果允许比较，展示 0% 与未评分数量 | 覆盖全未评分任务，均分保持空值 |

中文名称仅用于阅读和搜索，不修改原始语种代码、缓存键和分组口径。未知或自定义语种代码原样显示；当前系统的参考译文固定为中文，所以语言对明确展示到中文。

## 验证与实现约束

- 前端生产构建通过。
- 后端 148 项测试通过，新增 8 项导航与一致性回归；覆盖历史语言数量、精确版本标识、列表 / 详情一致性、全未评分、筛选分页和 ID 特殊字符。
- 统计使用批量 SQL：结果列表从 1 条扩到 21 条，查询数量不增加；16 个数据集的列表仍只使用 3 条 SELECT，避免为每行结果单独请求摘要。
- 浏览器使用隔离临时数据库，覆盖两版不同语言组成、相同模型多次评测、全未评分任务和 33 语种数据集，不调用外部 LLM。
- 浏览器 16 项操作验收通过，无 JavaScript 运行时错误及失败 API 请求；记录和截图见 [验收文件](usability-review-2026-09-07/browser-verification.json)。

本轮不需要数据库迁移。准确率与列表摘要由现有样本、分数及阈值即时计算，原始评分和任务状态保持可追溯。
